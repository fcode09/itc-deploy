# secret · the files of an instance's secrets/

Some services read a file from `instances/<name>/secrets/` (the Firebase JSON of the push notifications:
`FCM_CERT=/run/secrets/fcm.json`). `secret` says which ones the instance needs, whether they are there, and loads
the missing one: you leave the file on the server, give its path and it is put where it belongs (mode 600).
It never shows what is inside a file.

## Usage
$ ./deltactl secret list <instance>
$ ./deltactl secret check <instance>
$ ./deltactl secret add <instance> <variable|file> <path> [--force]

## Example
$ scp fcm.json user@server:~/
$ ./deltactl secret list colorado
$ ./deltactl secret add colorado FCM_CERT ~/fcm.json
$ ./deltactl deploy colorado

## What each one does
- `list`   shows the files the instance needs (variables that point to `/run/secrets/...`) and whether each one is there
- `check`  the same, but it ends with an error when one is missing or is not a JSON object (useful in a script)
- `add`    copies the file of this machine to `secrets/<name>`; the variable is given by its name (`FCM_CERT`)
           or by the name of the file (`fcm.json`)

## Options
- `--force`  replaces a file that is already in `secrets/` (without it, `add` refuses)

## Notes
- the file must be a JSON object of up to 128 KiB; if it is not, `add` says why and copies nothing
- the deploy does not start while one of these files is missing: `./deltactl deploy` and `./deltactl check` say so
- in the panel, the `f` key on that variable (the Variables view or the Variables tab) does the same asking only for the path

## Related

# images · available image versions

It lists the images loaded in this Docker by service and which instances use them.
It lists and, when asked, removes the versions nobody uses (`rm`, `prune`). Alias: `./deltactl versions`.

## Usage
$ ./deltactl images [service] [--json]
$ ./deltactl images rm <service>:<version>... [--yes]
$ ./deltactl images prune [service] [--keep N] [--dry-run] [--yes]

## How to read the table
The versions of each image go from the newest to the oldest **by creation date of the image** (a tag is only a name).
- `im-uno(current)` that instance uses the tag now
- `im-uno(previous)` is the previous version kept for rollback
- `unused (candidate for deletion)` no instance uses it
- `★` the most recent one this server can use: the newest by date among the tags that are versions (`1.2.3`, `v1.2.3`,
  `2026.11.3`) and of the server's architecture. It is the one `./deltactl new --s0-tag latest` picks
- `▲` a tag that moves (`latest`, or not a version): it cannot take you back and it is never the ★
- `✖` in ARQ: an image of another architecture; it would not start here
- If a lower version was created after a higher one (was an old one rebuilt?), the table warns under that image

## Options
- `service` shows only `s0` or only `s1`
- `--json` output for scripts (no colors); `used_by` always uses `(current)` and `(previous)`, whatever the language.
  It also has `created_at` (ISO 8601 date in UTC, empty when Docker gives none), `latest` (`true` on the ★),
  `compatible` (`false` for another architecture) and `kind` (`version`, `latest` or `other`)

## Removing versions nobody uses
`rm` removes the versions you name; `prune` removes every one that is left over of a service (or of all). Both ask first
(`--yes` skips it) and say how much space they free. **They touch no data and no instance**; to have a version again it
has to be loaded (`load`).
Never removed (it says why):
- the version an instance runs now (`current`)
- the **previous** one of an instance: the rollback needs it
- one a container uses, even a stopped one (an instance whose tag changed and was not deployed yet still runs the old one)
`prune` also always keeps the ★ (the most recent of the service) and `--keep N` leaves the N most recent of the ones left over.
`prune --dry-run` only says what it would remove. Docker is called without force: if it refuses, its reason is shown. When
another tag points to the same image only the name is taken off and no space is freed (the figure counts each image once).

## Examples
$ ./deltactl images
$ ./deltactl images s1 --json
$ ./deltactl images prune --dry-run
$ ./deltactl images prune s0 --keep 1 --yes
$ ./deltactl images rm s0:v2.1.0

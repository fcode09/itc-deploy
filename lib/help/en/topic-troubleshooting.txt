# Troubleshooting

Each item is: what you see → why it happens → what to do.

## When deploying
- `image X:tag is missing` → the tag is not loaded or the name does not match → `./deltactl images`, `./deltactl load <file>` or
  fix `S0_TAG`/`S1_TAG`/`S0_IMAGE`/`S1_IMAGE`
- `<VARIABLE> is empty` / `example value (CAMBIAR...)` → a required variable is not filled in → `./deltactl help variable
  <VARIABLE>`
- `FCM_CERT points to ... but secrets/... is missing` → the JSON is not there or the path does not start with `/run/secrets/` →
  `./deltactl help secrets`
- `'sN' is not active in 'x'` → the service is not in `COMPOSE_PROFILES` → add it in `.env.instance` → `./deltactl help services`
- `did not become healthy` → the service started but fails its check → `./deltactl logs <instance> <service>`
- `cannot talk to the Docker daemon` → Docker stopped or your user without permission → `sudo systemctl start docker` or add
  your user to the `docker` group
- `data/ does not belong to uid 1000` → the app might not be able to write → `sudo chown -R 1000:1000 instances/<instance>/data`

## When seeding (`init`)
- `already has data ... the seeds would DELETE it` → the database is not empty → it is an existing municipality: `./deltactl
  adopt <instance>`
- `s0 could not reach s1 over TCP` → `TCP_LISTEN_HOST=0.0.0.0` is missing in `.env.s1` or the s1 image does not support it →
  `./deltactl help network`
- `could not check Mongo` → wrong URI or Mongo unreachable from the container → check `MONGO_*` and `host.docker.internal`

## With the system running
- `configured X but running Y` → you changed the tag without deploying → `./deltactl deploy <instance> <service>`
- `tag X points to another image` → you rebuilt an image with the same tag → always use a new tag
- `unhealthy`, `restarting` → the service fails on start → `./deltactl logs`; if it is after an update, `./deltactl rollback`
- logs with `ECONNREFUSED ...:5050` (s0) or `...:7050` (s1) → optional services not deployed (Spider and AddressLocator) →
  `./deltactl help network`
- Gue answers 400 on some routes of a new instance → the initial data is missing → `./deltactl init`
- `s0` logs with `ENOENT ... media/notification/no-image.png` → that file is missing in
  `instances/<instance>/data/s0/media/notification/` → copy it from the current installation (PM2)

## Mongo goes down with many instances
Each instance opens hundreds of connections and files. With the default limit (1024 open files)
Mongo can go down with `EMFILE`: raise `nofile` to 64000 or more for the Mongo process.

## If none of this applies
$ ./deltactl status <instance>
$ ./deltactl logs <instance> <service>
$ ./deltactl help search <word from the error>

# Update an instance to a new version

## Idea
A new version is an image with a NEW tag. Never reuse a tag: the rollback
and the `status` warnings depend on every tag always pointing to the same image.

## Steps
- 1. on your PC, build with a new tag and save the image
$ docker build -t s1:1.3.0 .
$ docker save s1:1.3.0 | gzip > s1-1.3.0.tar.gz
- 2. copy it to the server and load it
$ scp s1-1.3.0.tar.gz user@server:/path/deltactl/
$ ./deltactl load s1-1.3.0.tar.gz
$ ./deltactl images
- 3. change the tag in `instances/colorado/.env.instance`: `S1_TAG=1.3.0`
- 4. deploy only that service
$ ./deltactl deploy colorado s1
- 5. verify: `CONFIG` and `RUNNING` must match and the state be healthy
$ ./deltactl status colorado

## Going back
$ ./deltactl rollback colorado s1
> It needs the previous image to still be loaded: do not use `docker image prune -a`.

## What does NOT happen when updating
- data is not seeded again (`deploy` never seeds)
- `data/`, `secrets/` and the Mongo databases are not touched

## Several instances
Each instance has its own tag: you can update one and leave others on the previous version.
Keep the old images until no instance uses them (`./deltactl images` marks them).

## If the version requires new variables
Add them to `.env.s0` or `.env.s1` BEFORE deploying (`./deltactl help variable` explains the known ones).

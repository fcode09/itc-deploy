# secret · los archivos de secrets/ de una instancia

Algunos servicios leen un archivo de `instances/<nombre>/secrets/` (el JSON de Firebase de las notificaciones:
`FCM_CERT=/run/secrets/fcm.json`). `secret` dice cuáles necesita la instancia, si ya están, y carga el que falta:
tú dejas el archivo en el servidor, das su ruta y se pone donde corresponde (con permisos 600).
Nunca muestra lo que hay dentro de un archivo.

## Uso
$ ./deltactl secret list <instancia>
$ ./deltactl secret check <instancia>
$ ./deltactl secret add <instancia> <variable|archivo> <ruta> [--force]

## Ejemplo
$ scp fcm.json usuario@servidor:~/
$ ./deltactl secret list colorado
$ ./deltactl secret add colorado FCM_CERT ~/fcm.json
$ ./deltactl deploy colorado

## Qué hace cada una
- `list`   muestra los archivos que la instancia necesita (variables que apuntan a `/run/secrets/...`) y si cada uno está
- `check`  lo mismo, pero termina con error si falta alguno o no es un objeto JSON (sirve en un script)
- `add`    copia el archivo de esta máquina a `secrets/<nombre>`; la variable se da por su nombre (`FCM_CERT`)
           o por el del archivo (`fcm.json`)

## Opciones
- `--force`  reemplaza un archivo que ya está en `secrets/` (sin ella, `add` se niega)

## Notas
- el archivo debe ser un objeto JSON de hasta 128 KiB; si no lo es, `add` dice por qué y no copia nada
- el despliegue no arranca mientras falte uno de estos archivos: `./deltactl deploy` y `./deltactl check` lo dicen
- en el panel, la tecla `f` sobre esa variable (vista Variables o pestaña Variables) hace lo mismo pidiendo solo la ruta

## Relacionado
- `./deltactl help secretos`, `./deltactl help variable FCM_CERT`

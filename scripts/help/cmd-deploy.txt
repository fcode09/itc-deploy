# deploy · levantar o actualizar una instancia

Valida la configuración, comprueba que las imágenes existan y levanta los servicios esperando a que
estén healthy. Con servicio, solo toca ese servicio. NUNCA siembra datos.

## Uso
$ ./itc deploy <instancia> [servicio]

## Qué hace, en orden
- 1. exige que las variables obligatorias estén completas (sin valores `CAMBIAR...`)
- 2. valida el compose de la instancia
- 3. con imágenes locales comprueba que existan en este Docker (si falta alguna, no cambia nada)
- 4. avisa si una etiqueta apunta ahora a otra imagen distinta de la desplegada
- 5. guarda las etiquetas anteriores para poder hacer rollback
- 6. levanta (con REGISTRY descarga las imágenes antes) y espera a healthy
- 7. registra las etiquetas desplegadas en `.deployed`

## Ejemplos
$ ./itc deploy colorado          # todos los servicios activos de la instancia
$ ./itc deploy colorado s1       # solo s1 (no toca s0)

> Con imágenes locales (REGISTRY vacío) nunca se descarga nada de internet.
> Si cambias `S1_TAG` y despliegas, Compose recrea solo el contenedor que cambió.

## Errores típicos
- `falta la imagen X:tag` → cárgala (`./itc load`) o corrige la etiqueta (`./itc images`)
- `FCM_CERT apunta a ... pero falta secrets/...` → copia el JSON a `secrets/` (`./itc help secretos`)
- `no llegó a healthy` → `./itc logs <instancia> <servicio>`; para volver atrás `./itc rollback`
- `no está inicializada` (aviso) → `./itc init` si es nueva, `./itc adopt` si ya tiene datos

## Relacionado
- `./itc help actualizar`, `./itc help imagenes`, `./itc help solucion-problemas`

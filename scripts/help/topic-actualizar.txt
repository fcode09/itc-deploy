# Actualizar una instancia a una versión nueva

## Idea
Una versión nueva es una imagen con una etiqueta NUEVA. Nunca reutilices una etiqueta: el rollback
y los avisos de `status` dependen de que cada etiqueta apunte siempre a la misma imagen.

## Pasos
- 1. en tu PC, construye con una etiqueta nueva y guarda la imagen
$ docker build -t s1:1.3.0 .
$ docker save s1:1.3.0 | gzip > s1-1.3.0.tar.gz
- 2. cópiala al servidor y cárgala
$ scp s1-1.3.0.tar.gz usuario@servidor:/ruta/itc-deploy/
$ ./itc load s1-1.3.0.tar.gz
$ ./itc images
- 3. cambia la etiqueta en `instances/colorado/.env.instance`: `S1_TAG=1.3.0`
- 4. despliega solo ese servicio
$ ./itc deploy colorado s1
- 5. verifica: `CONFIG` y `CORRIENDO` deben coincidir y el estado ser healthy
$ ./itc status colorado

## Volver atrás
$ ./itc rollback colorado s1
> Necesita que la imagen anterior siga cargada: no uses `docker image prune -a`.

## Qué NO pasa al actualizar
- no se vuelven a sembrar datos (`deploy` nunca siembra)
- `data/`, `secrets/` y las bases de Mongo no se tocan

## Varias instancias
Cada instancia tiene su propia etiqueta: puedes actualizar una y dejar otras con la versión anterior.
Conserva las imágenes antiguas hasta que ninguna instancia las use (`./itc images` las marca).

## Si la versión exige variables nuevas
Añádelas a `.env.s0` o `.env.s1` ANTES de desplegar (`./itc help variable` explica las conocidas).

## Relacionado
- `./itc help imagenes`, `./itc help servicios`
